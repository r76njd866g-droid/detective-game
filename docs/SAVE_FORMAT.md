# Сохранения Detective Game, версия 2

## Границы изменения

Слой `save-store.js` отвечает только за сохранение и восстановление состояния. Правила расследования, тексты, изображения, CSS и адреса семи глав остаются в HTML. `save-specs.js` содержит проверочные метаданные существующих глав V–VIII. Это ещё не единый игровой движок.

## Хранение

- Старые ключи `last_case_chapter_2_v1` … `last_case_chapter_4_v1` и `archive_case_chapter_5_v1` … `archive_case_chapter_8_v1` никогда не записываются и не удаляются новой версией.
- `detective:saves:v2:legacy-archive` — однократный архив точных строк старых записей, включая повреждённые. При невозможности записать архив миграция прекращается.
- `detective:saves:v2:revision:<UUID>` — отдельная неизменяемая версия состояния прохождения. При записи требуется свободный ключ. Старые версии не удаляются.
- `detective:saves:v2:active` — только указатель для входа без параметров. Его изменение не затрагивает прогресс.
- `detective:saves:v2:import-archive:<UUID>` — исходные данные импортированного экспорта, сохранённые как инертный материал для восстановления. Они не записываются поверх рабочих или старых ключей.

Версия имеет поля `schemaVersion: 2`, `id`, `runId`, `parent`, `sequence`, `createdAt`, `data`. Данные: `label`, `branch: originals|belov`, `chapters: {"2": ChapterState, …}`. В `parent` записывается ID предыдущей версии; у нового прохождения — `null`.

ID создаётся через `crypto.randomUUID()`; игра рассчитана на HTTP localhost или HTTPS. Для запуска использовать `python -m http.server 8080`, как и прежде. Не открывать разные главы на разных портах.

## Прохождения и вкладки

Параметр `?run=<UUID>` фиксирует выбранный путь в адресе вкладки. Старые пути `index.html`, `chapter3.html` … `chapter8.html` продолжают работать. Ссылки между главами автоматически получают этот параметр. Страница `saves.html` позволяет выбрать нужный путь; она не является новой игровой главой.

Повтор главы создаёт новый ID, копирует предшествующие главы и начинает текущую заново; последующие главы в новый путь не переносятся. Возврат к развилке IV сохраняет найденные улики и выводы, очищает решение и создаёт отдельный путь без V–VIII. Старый путь остаётся доступен.

Если вкладка пытается записать изменённое состояние после записи другой вкладкой, создаётся отдельный путь. У `localStorage` нет транзакционного compare-and-swap: при строго одновременной записи двух вкладок возможны два конца цепочки с общим родителем. Обе версии остаются в хранилище и показаны на странице сохранений. Ничьи данные не перезаписываются. При обычном продолжении выбирается версия с максимальными `sequence`, затем `createdAt`, затем `id`; для выбора другой используется список сохранений.

Открытие конкретной версии через `revision` позволяет продолжить её отдельно, если уже появилась более новая. Сохранение идентичного состояния не создаёт лишнюю версию.

## Миграция

Старый формат не содержит ID прохождения. Поэтому восстановить историческую принадлежность каждой главы достоверно невозможно. Миграция создаёт явно обозначенные восстановленные снимки по ветке, сохраняя исходные строки. Если IV и поздние главы относятся к разным веткам, создаются отдельные пути; противоречащая глава IV в другой путь не подставляется. Это восстановленные группы, а не доказательство единого исходного прохождения.

Проверяются JSON, типы, допустимые идентификаторы, перечисления, наличие оснований для выводов и завершения, ответы задач, согласованность ветки. Повреждённая запись не применяется. Для повреждённой новой версии используется предыдущая корректная версия, если она существует; показывается предупреждение. При отсутствии корректных данных запускается пустое состояние в новом пути. Исходные повреждённые данные сохраняются.

При входе без выбранного ID в восстановленную группу, в которой нет текущей главы, проверяется другая восстановленная группа. Поэтому старое решение IV не скрывает существующее сохранение V–VIII другой ветки. Явно выбранное прохождение всегда остаётся закреплено; этот переход применяется только к автоматически восстановленным группам.

Архив миграции создаётся один раз: изменения, сделанные позднее в старой версии игры, не смешиваются автоматически с новыми прохождениями. Их исходные ключи доступны в экспорте для отдельного восстановления.

## Экспорт и импорт

Страница сохранений скачивает JSON с `format: detective-game-progress`, `schemaVersion: 2`, `exportedAt`, `runs` и `raw`. `runs` содержит последние независимые пути, `raw` — также старые строки и все сохранённые версии для технического восстановления. При ошибке записи кнопка предупреждения экспортирует и текущее состояние из памяти.

Импорт проверяет весь список и тип архива до записи, затем создаёт новые ID для импортированных путей. Старые данные не заменяются. При нехватке места импорт может завершиться частично: уже добавленные новые пути остаются, прежние записи неизменны. Повтор импорта может добавить копии; это сознательно безопаснее замены. Максимум — 100 путей и файл 20 МБ в интерфейсе. Произвольный старый JSON не исполняется и не восстанавливается напрямую в `localStorage`.

Между origin браузера автоматического переноса нет: экспортировать по прежнему адресу, импортировать по новому. Пока старая версия сайта не обновлена, её записи также живут отдельно. Откат к старому HTML увидит старые записи v1, но не новый прогресс v2. Перед откатом экспорт обязателен для сохранения новых результатов.

## Эксплуатационные ограничения

Неизменяемая история расходует квоту браузера. Автоматического удаления нет; при отказе записи появляется предупреждение и доступен экспорт. В этой версии не внедрены сжатие, IndexedDB, синхронизация устройств или очистка истории. Их можно проектировать отдельно, с явным резервированием данных.

Подмена сохранений пользователем не предотвращается криптографически. Проверки защищают от случайных повреждений и некорректных импортов, а не от целенаправленного изменения локальных данных.
