## Обнаруженные проблемы и проваленные проверки

### M-01. Перекрытие ведомости в IV на 320×568

- Цель: `chapter4.html`, `data-object="manifest"`.
- Касание по центру принимает `data-object="phone"`; штатный тест касания завершается тайм-аутом.
- Повторное точное воспроизведение подтвердило дефект. Касание открытого края ведомости работает. После поворота в альбом центр также работает.
- Влияние: затруднён сбор обязательного документа; нельзя считать узкий портретный интерфейс принятым.

### M-02. Перекрытие книги в VIII на 360×800

- Цель: `chapter8.html`, `data-object="register"`.
- Касание по центру принимает `data-object="command"`.
- Край книги доступен; в альбомной ориентации центр работает. Принудительные клики не использовались для объявления проверки успешной.
- Влияние: аналогичная проблема с обязательным материалом финальной главы.

### M-03. Заголовок II выходит за 320 CSS px

Граница правых элементов — 332,09 px при заданном viewport 320 px: обрезается около **12,09 CSS px**, включая часть ссылки «Сохранения». Замер относительно `innerWidth` скрывал бы проблему, поскольку сам `innerWidth` расширился из-за overflow. Отдельный геометрический тест сравнивает с заданным viewport и возвращает FAIL. Проверена геометрия 22 завершённых экранов; ещё два прерваны перекрытиями выше.

Эти три дефекта не исправлялись: задание запрещает менять дизайн и просит проверку. Нужна отдельная техническая коррекция областей нажатия и размещения управления с сохранением изображений и сюжета. До неё допустима только ограниченная исследовательская приёмка с явными замечаниями, а не заявление о готовности всех телефонов.

### Неблокирующее замечание

В Chromium возможен запрос отсутствующего `/favicon.ico` с ответом 404. Это отражено в console/network, не является исключением игрового JavaScript и не ломает изображения или сохранения. Для этого задания иконка не добавлялась.

### Ошибки самого нового тестового стенда

Первичные запуски обнаружили неверный метод очистки контекста, несовместимый параметр device preset для persistent context, обращение к скрытой десктопной кнопке вместо мобильного журнала и преждевременное чтение URL после касания. Они исправлены только в тестах. Маршруты, мобильный жизненный цикл и перезапуски повторно проверены успешно. Эти технические FAIL не смешиваются с тремя воспроизводимыми дефектами игры. Первичные и повторные логи сохранены отдельно.

## Staging: подготовлено и не выполнено

Готовая проверенная копия: `work/staging-audit/package/site/`.

- ZIP: `work/staging-audit/package/detective-game-staging.zip`.
- Манифест SHA-256: `work/staging-audit/package/manifest.json`.
- Только allowlist из 10 публичных игровых файлов. Не включены `.git`, отчёты, browser profiles, выгрузки прогресса и настройки среды.
- Проверены соответствие исходному коммиту, ZIP и отсутствие характерных маркеров приватных ключей/токенов. Это целевая проверка небольшой поставки, не обещание универсального поиска любых секретов.
- Локальный сервер разрешает только игровые маршруты, не выдаёт листинг каталогов и служебные файлы.

**Удалённый тестовый URL: отсутствует.** Доступный Sites описывает все deployment URL как production URL и не предоставляет отдельную preview-операцию в этой сессии. Поэтому не создавался новый сайт, не запрашивались credentials, не подключался сервис и не запускалась публикация под названием staging. Текущий сайт, основной домен и настройки репозитория не менялись.

Локальные URL, использованные тестами, доступны только внутри среды; серверы после проверок остановлены. Это не ссылки для телефона владельца.

Инструкция воспроизводимой локальной подготовки и требования к внешнему хостингу: [STAGING_SETUP.md](STAGING_SETUP.md). Для телефона нужен отдельный **HTTPS** origin: LAN-адрес по обычному HTTP не является полноценной заменой, поскольку `crypto.randomUUID()` требует безопасного контекста.

## Что не проверено

- Настоящие iPhone/Android, Safari/iOS, Firefox и WebKit: устройства и соответствующие браузерные бинарники отсутствуют, не устанавливались.
- Реальное звучание, тихий режим, блокировка экрана и возобновление аудио.
- OS file picker, клавиатура телефона, screen reader, жесты браузера и вытеснение хранилища ОС.
- Сохранения реальных пользователей: проверялись только синтетические данные.
- Работа конкретного внешнего HTTPS хостинга, авторизация staging и перенос между действующим и новым доменом.

## Что требуется от владельца

1. Выбрать настоящий preview/staging-хостинг с отдельным HTTPS origin и согласовать его подключение. Альтернатива — отдельное разрешение на постоянную приватную публикацию нового изолированного сайта в Sites. Это не выполнено автоматически.
2. Решить, исправлять ли M-01–M-03 до телефонной приёмки. До исправления известен обход через альбомную ориентацию, но это не успешная приёмка портретного режима.
3. Пройти [PHONE_TEST_SCENARIOS.md](PHONE_TEST_SCENARIOS.md) на реальном Safari/iPhone и Chrome/Android, записав модель, версии, сеть и результаты.
4. После появления фактического URL отдельно проверить все маршруты, HTTPS, ресурсы и сохранения именно на нём. Не публиковать выгрузки пользователей вместе с сайтом.

**Production-релиз не подготовлен к утверждению этим отчётом.** Сборка пригодна для ограниченной изолированной проверки владельцем с перечисленными замечаниями; удалённое размещение ждёт выбора и согласования способа staging.
